# Product FAQ and Customer Questions

Answer the questions that stop people buying, on the page where they stop. Write an answer once and show it on every product, or attach it to a single product. Shoppers can ask their own question from the product page; it lands in a moderation queue, and publishing your answer turns it into a FAQ entry.

**Compatibility:** PrestaShop 1.7.0 and above, including PrestaShop 8 and 9. Multilingual and multistore.

**Installable zip:** the archive GitHub generates on the releases page is a source snapshot, not an installable module — PrestaShop rejects it because the folder inside carries the version number. Download the ready-to-install zip from [megventure.com](https://megventure.com/en/free-modules/94-prestashop-product-faq-customer-questions.html).

## What it does

- **Write an answer once, reuse it everywhere.** An entry with no product attached is shown on *every* product page. "Do you ship to Germany?" and "How long is the licence valid?" are written once, not once per product. An entry attached to a product shows only there. Product-specific entries sort above shared ones.
- **Shoppers ask, you moderate.** A short form on the product page lets a visitor ask a question. Nothing is published automatically: the question arrives unpublished, you write the answer, and publishing it turns the pair into an ordinary FAQ entry that then behaves like any other. You can restrict the form to logged-in customers, or turn it off entirely.
- **One FAQ page.** All published entries also appear on a single `/faq` page, generated by the module. It can be turned off if you only want the product-page blocks.
- **Language fallback.** If an entry has no translation in the visitor's language, the module can show the shop's default language instead of showing nothing. This is a setting, not a silent default.
- **Two e-mails, both optional.** One tells you a new question arrived; one tells the shopper their question has been answered. English and Turkish templates ship with the module; other languages fall back to English until you add them.
- **Flood protection.** By default the same e-mail address can send at most three questions per hour. Set it to zero to disable.
- **GDPR.** The module answers PrestaShop's data-export and data-erasure hooks, so a customer's questions are included in an export and removed on erasure.

## What it deliberately does not do

**It does not add FAQPage structured data.** Google stopped showing FAQ rich results on 7 May 2026 and removed the documentation in June, so the markup no longer produces the boxes people remember. What still works is what this module does: putting the questions and answers into the HTML the server sends, where shoppers read them and where search engines and AI answer engines can quote them.

If you do want FAQPage markup for other consumers, our [AI Visibility Toolkit](https://megventure.com/en/prestashop-modules/93-ai-visibility-toolkit-crawler-policy-llms-txt.html) reads this module's published entries and emits it — the two are designed to be used together, and neither duplicates the other's job.

**It does not render anything with JavaScript after the page loads.** The entries are in the server response. That is the whole point; a crawler that does not run scripts still sees the text.

## Installation

1. Back Office → Modules → Upload a module, select the zip, install.
2. Open **Configure**. The defaults are usable immediately — the product-page block and the FAQ page are on, the ask form is on, and questions go to your shop e-mail.
3. Add your first entry. Leave the product field empty to show it on every product.

## Configuration

The configure page is organised top to bottom:

1. **Where it shows** — product-page block on/off, whether shared entries appear on product pages, the `/faq` page on/off, and whether the first entry starts expanded.
2. **Languages** — fall back to the shop default language when a translation is missing.
3. **Questions from shoppers** — the ask form on/off, who may use it (everyone or logged-in customers only), how many questions one e-mail address may send per hour, and an optional CMS page to link as the consent text.
4. **Mail** — notify on a new question, the address to notify, and whether to e-mail the shopper when you publish the answer.
5. **Entries** — the list, with filters for pending and published, and paging.

Above 800 products the "shown on" product picker becomes a plain ID field. A select carrying every product in a large catalogue is a page that takes seconds to render and megabytes to send.

## Data

Three tables: `megfaq` (the entry and its scope), `megfaq_lang` (question and answer per language), `megfaq_shop` (which shops it belongs to). Uninstalling the module removes all three.

## A note on installing

The two GDPR hooks are registered as optional. PrestaShop creates those hooks on demand, which means registering them writes a row to the hook table — and on a shop where that write fails (a restored database that lost an `AUTO_INCREMENT` is the case we actually hit), the module used to refuse to install with no indication of which of twenty steps had failed. A FAQ module that cannot answer an export request is a smaller problem than a FAQ module that will not install, so those two now fail loudly in the log and quietly on screen.
